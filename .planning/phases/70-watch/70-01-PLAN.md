  新建 `src/cli/watch/offsets.rs`，按 RESEARCH Pattern 2 实现三个 pub(super) 函数。具体要求：

  1. **文件顶部 doc comment**：
  `//! Phase 70: _watch_offsets 辅助表读写。每次调用打开新连接，与 SqliteExporter 的 EXCLUSIVE 锁隔离（per D-05）。`

  2. **use 语句**：
  ```
  use rusqlite::{Connection, params};
  use std::collections::HashMap;
  use std::path::{Path, PathBuf};
  ```

  3. **`pub(super) fn ensure_offset_table(database_url: &str) -> rusqlite::Result<()>`**（per D-11）
  - 打开 Connection，执行 `execute_batch` 创建表：
    SQL: `CREATE TABLE IF NOT EXISTS _watch_offsets (path TEXT NOT NULL PRIMARY KEY, byte_offset INTEGER NOT NULL);`
  - 返回 `Ok(())` 或 propagate rusqlite::Error。
  - 函数体 ≤40 行。

  4. **`pub(super) fn load_offsets(database_url: &str) -> HashMap<PathBuf, u64>`**（per D-06 + D-11）
  - 打开 Connection；open 失败 → `log::warn!("watch::offsets::load_offsets open: {e}")` 并返回空 HashMap（不 panic）。
  - prepare `SELECT path, byte_offset FROM _watch_offsets`；prepare 失败（如表不存在）→ 返回空 HashMap，不报错（Pitfall：首次运行表不存在是正常状态）。
  - query_map：path 作为 String，byte_offset 作为 i64。
  - 过滤：`if offset >= 0 { Some((PathBuf::from(path), offset as u64)) } else { None }`（per Pitfall 2：避免 i64 负值产生错误 u64 极大值）。
  - 函数体 ≤40 行——若超出，可提取 `fn rows_to_map(stmt, ...) -> HashMap<...>` 私有辅助。

  5. **`pub(super) fn save_offset(database_url: &str, path: &Path, offset: u64)`**（per D-07/D-08 + D-11）
  - 返回 `()`（不返回 Result，per D-07：持久化失败 log::warn! 但不中断 watch）。
  - 打开 Connection；open 失败 → `log::warn!("watch::offsets::save_offset open: {e}")` 并 return。
  - 执行 `INSERT OR REPLACE INTO _watch_offsets (path, byte_offset) VALUES (?1, ?2)`，使用 `params![path.to_string_lossy().as_ref(), offset as i64]`（i64 转换：u64 在文件大小范围内不会溢出）。
  - execute 失败 → `log::warn!("watch::offsets::save_offset write: {e}")`，不 panic、不 Err。
  - 函数体 ≤40 行。

  6. **`#[cfg(test)] mod tests`** 包含上述 5 个测试。使用 `tempfile::NamedTempFile` 生成临时 .db 路径（提示：`let tmp = NamedTempFile::new().unwrap(); let url = tmp.path().to_str().unwrap();` —— tmp 持有到测试结束，避免提前删除）。注意 use 语句：`use tempfile::NamedTempFile;`（现在 tempfile 已是生产依赖，#[cfg(test)] 块仍可使用）。
