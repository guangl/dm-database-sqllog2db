# Requirements: sqllog2db

**Defined:** 2026-06-07  
**Core Value:** 用户能够精确指定"导出哪些记录的哪些字段"——过滤逻辑清晰可配置，输出结果完全可控

## v1.20 Requirements

### 性能测量（BENCH）

- [x] **BENCH-01**: 开发者可以用 hyperfine 测量 CLI 冷启动延迟，结果存入 BENCHMARKS.md
  — ✅ Validated: v1.20 Phase 72 — `--version` 2.1ms、`validate` 2.2ms，较 v1.9 降 ~0.7ms，写入 BENCHMARKS.md Phase 72 段落
- [x] **BENCH-02**: 开发者可以用 `--save-baseline` 将 criterion 结果存档到 `benches/baselines/`，版本间对比有迹可循
  — ✅ Validated: v1.20 Phase 72 — `CRITERION_HOME=benches/baselines cargo bench -- --save-baseline v1.20` 存档完成

### SQLite 导出提速（SQLITE）

- [x] **SQLITE-01**: SQLite 导出支持 multi-row batch INSERT（缓冲 N 条记录，一次执行 `INSERT INTO t VALUES (…),(…),…`，减少逐行调用开销）
  — ✅ Validated: v1.20 Phase 73 — `row_buffer` + `flush_batch` + `sql_cache`，default batch size 64
- [x] **SQLITE-02**: benchmark 可以量化 multi-row INSERT 相较于当前单行模式的吞吐量提升
  — ✅ Validated: v1.20 Phase 73 — `bench_sqlite_multi_row_insert` group 量化对比写入 BENCHMARKS.md

### 内存与分配优化（MEM）

- [x] **MEM-01**: normalizer 热路径 HashMap key 不再每条记录重复 clone String（改用 Arc 或调整生命周期，减少堆分配）
  — ✅ Validated: v1.20 Phase 74 — ParamBuffer 重构为二级 HashMap，DML 查询路径改用 `&str` 零分配查询
- [x] **MEM-02**: CSV line_buf 初始容量按典型 SQL 长度预热，减少 Vec grow 次数
  — ✅ Validated: v1.20 Phase 74 — `CsvExporter::new()` `line_buf: Vec::with_capacity(4096)`

### 代码结构重构（STRUCT）

- [x] **STRUCT-04**: `cli/run/parallel.rs` 与 `cli/run/sqlite_parallel.rs` 的公共逻辑（文件收集、记录处理、错误统计）提取为共享模块，消除重复代码
  — ✅ Validated: v1.20 Phase 75 — `record_iter.rs::iterate_records` 共享模块，净消除 ~80 行重复代码

### 异步解析路径（ASYNC）

- [x] **ASYNC-01**: 将解析路径从同步 API 切换为 `dm-database-parser-sqllog` 的 async API，解析主循环使用 `.await`（crate 已原生支持 async，添加 tokio 运行时并迁移调用点）
  — ✅ Validated: v1.20 Phase 76 — `#[tokio::main]` + `AsyncLogParser` 全解析路径，503 tests 全绿，3.8MB release
