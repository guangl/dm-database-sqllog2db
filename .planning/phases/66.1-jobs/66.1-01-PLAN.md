<objective>
Phase 66 在 tests/integration.rs 中新增了三条并行集成测试,但两个系统性缺陷使并行路径在单核 CI 上根本不执行,且即使执行也无法暴露跨文件聚合 bug:

(1) **缺陷 1 — jobs 参数不可控**:`handle_run` 内部用 `std::thread::available_parallelism()` 动态获取 CPU 核数作为 jobs,并以 `jobs > 1` 作为并行触发条件之一。单核 CI 环境下 jobs=1,并行路径永远不触发,测试退化为顺序路径(等于无价值)。

(2) **缺陷 2 — 测试数据同构**:`write_test_log` 生成的多个文件内容完全相同(同 user、trxid 从 0 起连续)。两文件 id=0..N 内容重复时,排序后集合比较无法区分"A 的所有记录 + B 的零记录"与"A、B 各 N 条"。

本 plan 通过两项变更修复:
- (a) 在 `handle_run` 签名末尾追加 `jobs_override: Option<usize>` 参数(方案 C,最小侵入)。生产调用点传 `None`(行为等价);测试传 `Some(2)` 强制并行。
- (b) 新增 `write_heterogeneous_log(path, count, trxid_offset, username)` helper,使各文件 trxid 空间不重叠、user 不同、记录数可不同,任何聚合 bug 在 `assert_eq!(seq_lines, par_lines)` 上立即失败。

Purpose: 让 v1.17 的并行 CSV 路径在所有 CI 环境(含单核 macOS Actions runner)下都被实际执行并被强测试断言覆盖,堵住"测试通过但并行未跑"的盲点。

Output:

- src/main.rs / src/cli/run/tests.rs / benches/*.rs — 35+ 调用点同步补 None
- tests/integration.rs — 新 helper + 2 条强制并行测试 + 21 处现有 handle_run 调用同步补 None
- 三道质量门禁(cargo test / cargo clippy --all-targets -- -D warnings / cargo fmt --check)全绿
