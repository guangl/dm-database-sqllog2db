    == 编排脚本 run_all.sh ==

    创建 `run_all.sh`，功能如下：

    ### 全局设置
    - 设置 `set -euo pipefail` 严格模式
    - 定义 PROJECT_ROOT（脚本目录的 `../../..` → 项目根目录）
    - 定义 BINARY="cargo run --"（或使用 `target/release/sqllog2db` 如果已构建）
    - 定义临时工作目录（使用 `mktemp -d`，RUST 测试模式）
    - 定义 `RESULT_DIR` 存储所有测试输出
    - 定义 `PASS=0` `FAIL=0` 计数器
    - 定义 `CHECKLIST_FILE="VERIFICATION-CHECKLIST.md"` 在 phase 目录下

    ### 测试日志生成函数
    - `generate_test_logs()`:
      使用 `tests/integration.rs` 的 `write_test_log()` 模式编写：
      生成 3 个日志文件到临时目录：
      - `test_logs/dml.log` (500 行): user:TESTUSER, user:OTHERUSER 各一半，trxid 递增，exec_time 从 `(i*13)%1000` 模式
      - `test_logs/ddl.log` (100 行): 包含 "DROP TABLE" / "CREATE TABLE" SQL 内容，user:TESTUSER
      - `test_logs/normal.log` (200 行): 混合 user:TESTUSER 和 user:EXCLUDE_USER，exec_time 从低到高
      生成时写入原始 `.log` 文件（使用 `EP[0] sess:0x{i:04x} user:{user} trxid:{i} stmt:0x1 appname:App ip:10.0.0.1` 格式）。
      总记录约 800 行，足够验证但运行快速。
      在 dml.log 中故意混入 2-3 行格式错误的记录（用于错误日志验证）。

    ### 验证函数（按 KEEP 组织）
    每个验证函数接收 `RESULT_DIR` 路径，执行验证步骤，通过时输出 `PASS: ...`，失败时输出 `FAIL: ...`，返回 0/1。

    **check_keep_01_csv_export()**:
    1. 使用 config_csv.toml 运行 `sqllog2db run -c config_csv.toml`
    2. 验证 output.csv 存在且行数 > 1（有数据行 + 表头）
    3. 验证 CSV 表头包含预期字段（ts, sql, username 等）
    4. 计算数据行数并输出

    **check_keep_02_sqlite_export()**:
    1. 使用 config_sqlite.toml 运行导出
    2. 验证 output.db 存在
    3. 使用 `sqlite3 output.db "SELECT COUNT(*) FROM sqllog_records;"` 获取行数
    4. 使用 `sqlite3 output.db "SELECT username, sql FROM sqllog_records LIMIT 3;"` 抽查关键字段（D-10）
    5. 如果上一步 CSV 导出已完成，对比行数（D-10）

    **check_keep_03_filters()** (分 4 个子函数):
    - `_include()`: 使用 config_include.toml 导出，验证 CSV 中所有记录 user=TESTUSER，且行数 < 总行数
    - `_exclude()`: 使用 config_exclude.toml 导出，验证 CSV 中没有 user=EXCLUDE_USER 的记录
    - `_indicators()`: 使用 config_indicators.toml 导出，验证所有记录 exec_time_ms >= 50
      注意: 需要 CSV 包含 exec_time_ms 列（D-02: 验证完整功能）
    - `_sql()`: 使用 config_sql_filter.toml 导出，验证 CSV 中所有 sql 列包含 "DROP"
    - `_combined()`: 使用 config_all_filters.toml 导出，验证输出存在

    **check_keep_04_parameter_normalization()**:
    1. 使用 config_params.toml 运行导出（CSV + SQLite 双路）
    2. 验证 CSV 中包含 normalized_sql 列
    3. 验证 SQLite 中也包含 normalized_sql 列
    4. 对比 CSV 和 SQLite 总行数一致（D-05）
    5. 抽查 3 行，验证 normalized_sql 中的占位符替换正确（如 `?` 替换了数字字面量）

    **check_keep_05_parallel_csv()**:
    1. 确保 test_logs/ 中有 3+ 个文件（generate_test_logs 已生成）
    2. 顺序路径: `sqllog2db run -c config_parallel_csv.toml --jobs 1 -o out_seq.csv`，计时
    3. 并行路径: `sqllog2db run -c config_parallel_csv.toml --jobs 4 -o out_par.csv`，计时
    4. 验证两个 CSV 内容一致（排序后 diff，D-04 输出正确性）
    5. 比较时间，输出并行加速比

    **check_init_template()** (D-08):
    1. `sqllog2db init -o /tmp/sqllog2db_test_config.toml --force`
    2. 验证文件存在
    3. `sqllog2db validate -c /tmp/sqllog2db_test_config.toml`
    4. 验证 validate 成功（退出码 0）

    **check_error_log()** (D-11):
    1. 使用 config_error_log.toml 运行导出（测试日志中已混入格式错误行）
    2. 验证 error_test.log 存在且非空（有错误行被写入）
    3. 输出错误行数

    ### 主流程
    ```bash
    main() {
        1. 创建临时工作目录
        2. generate_test_logs          # 生成测试日志
    ```
