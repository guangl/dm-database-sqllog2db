# Milestone v1.10: 质量加固与体验优化

**Status:** ✅ SHIPPED 2026-05-21

**Total Plans:** 8（Phase 35: 1, Phase 36: 3, Phase 37-40: 各 1）

## Overview

v1.10 完成了 v1.7 精简后的质量补全工作：重构错误处理体系（类型细分 + 非致命继续处理 + 3 级退出码），增加 stdin 管道输入支持，引入 indicatif 进度显示，以及对 CSV/SQLite/Pipeline/参数归一化/并行处理的全面端到端验证（487 个测试）。

## Milestone Summary

**Key Decisions:**

- 错误类型细分为 ConfigError/FileError/ParserError/ExportError，每类独立实现 is_fatal()
- ErrorStats 结构体（非嵌入 Error 枚举）跟踪运行期错误统计，传递给 UX 层
- 3 级退出码（0/1/2）替代旧的按错误类型映射的退出码方案
- stdin 通过 /dev/stdin 路径映射实现，不改变现有 --input 参数结构
- indicatif 进度条取代 eprintln 进度输出，非终端自动退化
- Phase 39-40 合并为单次提交，避免中间不可运行状态

**Issues Resolved:**

- v1.7 精简后遗留的 3 项技术债全部在 Phase 34 闭合
- 非致命错误以前会终止整个导出，现在正确继续处理
- 旧退出码按错误类型分散（2/3/4/130），现在统一为 0/1/2/130

**Issues Deferred:**

- MultiProgress 多级进度条（P1，改用单行进度条）
- 数值错误码系统 E001/E002（thiserror Display 足够）
- 上游 parser crate 添加 from_reader() API（超出本项目范围）

**Technical Debt Incurred:**

- Phase 37-40 跳过了 GSD 规划流程，SUMMARY.md 为事后补录
- stderr 进度条与非致命错误输出可能互相干扰（Phase 38 注释中有 TODO）
