<!-- Config structure from actual `sqllog2db init -o config.toml --force` output -->

v1.4 nested config format has the following top-level sections:
- [sqllog] — log file paths and patterns
- [logging] — log level and error file
- [replace_parameters] — SQL parameter replacement (legacy, kept for backward compat)
- [template] — template normalization and aggregation
- [filter] — shared filter settings (record limit)
  - [filter.include] — include filter rules (AND semantics)
  - [filter.exclude] — exclude filter rules (OR-veto)
  - [filter.indicators] — transaction-level indicator filter
  - [filter.sql] — transaction-level SQL filter
- [charts] — SVG chart generation settings
- [resume] — incremental resume state tracking
- [exporter.csv] — CSV exporter settings
- [exporter.sqlite] — SQLite exporter settings

Key field details (from src/config.rs):
- sqllog.path: String, no default, required — path to log file or directory
- sqllog.pattern: Option\<String\>, default None — file glob pattern
- exporter.csv.file: String, default "output/sqllog.csv"
- exporter.csv.overwrite: bool, default false
- exporter.csv.delimiter: char, default ','
- exporter.csv.ordered_indices: Vec\<usize\>, default empty (all fields)
- filter.max_record_limit: usize, default 0 (no limit)
- template.enable: bool, default false
- template.normalize_template: bool, default false
- template.aggregator_mode: String, default "hdrhistogram"
- charts.top_n: usize, default 10
- charts.frequency_bar: bool, default false
- charts.latency_hist: bool, default false
- charts.trend_line: bool, default false
- charts.user_pie: bool, default false
- logging.level: String, default "info"
- logging.file: Option\<String\>, default None

Section ordering in init output:
[sqllog] → [logging] → [replace_parameters] → [template] → [filter] + sub-tables → [charts] → [resume] → [exporter.csv] → [exporter.sqlite]
</interfaces>

    **Section structure for each config block (per D-04):**
    Each config block follows this format:

    1. Section title: `## [section_name]` — shows the TOML section header
    2. Brief description (1-2 sentences): what this section does
    3. Annotated TOML example:
       ````toml
       [sqllog]
       # Path to DM SQL log file(s). Can be a single file or directory.
       path = "sqllogs"
       # Optional glob pattern for file matching (e.g., "*.log")
       # pattern = "*.log"
       ````
    4. Field table:

       | Field | Type | Default | Description |
       |-------|------|---------|-------------|
       | `path` | String | *(required)* | Path to log file or directory containing .log files |
       | `pattern` | String | `null` (optional) | Glob pattern to filter files when `path` is a directory |
    5. Notes section: usage tips, common mistakes, edge cases

    **Config Block 1: `[sqllog]` (per D-03)**
    Title: `## [sqllog]`
    - Path specification: directory vs single file
    - Glob pattern filtering
    - Notes: relative paths are relative to current working directory; absolute paths recommended for automation

    **Config Block 2: `[logging]` (per D-03)**
    Title: `## [logging]`
    - Log level (trace/debug/info/warn/error), default "info"
    - Error file: separate file for parse errors (none by default; errors go to stderr)
    - Notes: production use should set `level = "warn"` to reduce noise; error file captures parse failures without crashing

    **Config Block 3: `[filter.include]` and `[filter.exclude]` (per D-03)**
    Title: `## [filter.include] and [filter.exclude]`
    Applies to both include and exclude filters since they share the same structure.
    - Record-level filtering
    - Field-based regex matching (AND semantics for include, OR-veto for exclude)
    - Fields field: list of filter rules
    - max_record_limit at [filter] level
    - Notes: include + exclude combine as (include_AND) AND (NOT exclude_OR); all fields within one filter rule are AND-ed; multiple rules are also AND-ed

    **Config Block 4: `[template]` (per D-03)**
    Title: `## [template]`
    - enable flag
    - normalize_template: SQL fingerprint normalization (parameter stripping)
    - aggregator_mode: "hdrhistogram" (currently the only mode)
    - latency_buckets: array of bucket boundaries in ms
    - Notes: requires [charts] to generate visual output; dual output (CSV + SQLite) available

    After writing these blocks, verify the TOML examples parse correctly by running `cargo run -- validate -c /tmp/test-config.toml` with a test config file.

    **Config Block 5: `[charts]` (per D-03)**
    Title: `## [charts]`
    - output_dir: where SVG files are written
    - top_n: number of top templates to display
    - Four chart type flags: frequency_bar, latency_hist, trend_line, user_pie
    - Notes: charts are generated after template aggregation; output filenames are fixed (top_n_frequency.svg, latency_histogram_{key}.svg, frequency_trend.svg, user_schema_pie.svg); requires [template].enable = true

    **Config Block 6: `[exporter.csv]` (per D-03)**
    Title: `## [exporter.csv]`
    - file: output CSV path
    - overwrite: whether to overwrite existing file
    - delimiter: column separator (default comma)
    - ordered_indices: field projection — list of field indices to include, in desired order
    - Notes: ordered_indices is zero-indexed; empty = all fields in default order; CSV uses itoa zero-allocation formatting for performance (~5.2M rec/s)

    **Config Block 7: `[exporter.sqlite]` (per D-03)**
    Title: `## [exporter.sqlite]`
    - file: output SQLite database path
    - table: target table name
    - overwrite: drop and recreate table if exists
    - ordered_indices: same as CSV exporter
    - Notes: uses batch INSERT + PRAGMA optimizations for throughput (~1.1M rec/s); creates both sqlog_records table and _templates table when template aggregation is enabled

    **Config Block 8: `[features.replace_parameters]` (per D-03)**
    Title: `## [features.replace_parameters]`
    - This is a legacy section from pre-v1.4 config format, kept for backward compatibility
    - contains replacement rules for SQL parameter normalization
    - Notes: In v1.4, parameter normalization is handled by [template].normalize_template; use [template] section instead. This section exists for configs generated by older versions.

    **Appendix: Config Inheritance and Override Rules**
    Title: `## Appendix: Config Behavior Notes`
    - Config is loaded from the file specified by `-c` flag (default: sqllog2db.toml)
    - Optional sections can be omitted entirely — defaults apply for all fields
    - Exporter priority: CSV > SQLite (only one exporter active per run)
    - Filter priority: include before exclude within each record
    - Pipeline fast path: when no filters, template, or charts are enabled, entire pipeline is bypassed for zero overhead
    - Config validation runs via `sqllog2db validate -c config.toml` and reports all errors at once (not fail-fast)
