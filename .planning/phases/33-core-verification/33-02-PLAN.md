<task type="auto">
  <name>Task 2: 运行性能基准测试并对比基线</name>
  <files>benches/BENCHMARKS.md</files>
  <read_first>
    benches/BENCHMARKS.md
  </read_first>
  <action>
    运行全部三个 benchmark 套件，与 v1.0 保存基线对比，检测回归。

    执行步骤：

    步骤 1: 运行全部 benchmark（无基线对比，获取原始测量值）
    ```bash
    cargo bench 2>&1 | tee target/bench_results_raw.txt
    ```

    步骤 2: 对包含 v1.0 baseline 的 benchmark 组执行基线对比
    ```bash
    CRITERION_HOME=benches/baselines cargo bench --bench bench_csv -- --baseline v1.0 2>&1 | tee target/bench_csv_baseline.txt
    CRITERION_HOME=benches/baselines cargo bench --bench bench_sqlite -- --baseline v1.0 2>&1 | tee target/bench_sqlite_baseline.txt
    CRITERION_HOME=benches/baselines cargo bench --bench bench_filters -- --baseline v1.0 2>&1 | tee target/bench_filters_baseline.txt
    ```

    注意：某些 benchmark group（如 csv_format_only、exclude_* 等）没有 v1.0 saved baseline，
    criterion 会报告 `Baseline 'v1.0' must exist` 错误。对这些 group 跳过基线对比，
    使用步骤 1 的原始测量值对照 BENCHMARKS.md 的硬性指标手动比较即可。

    步骤 3: 分析回归情况（按 D-18）
    - 对比 criterion 输出的 `Performance has improved` / `has regressed` / `No change` 标识
    - 对比 BENCHMARKS.md 中的 v1.0 baseline 硬性指标（csv_export/10000: 2.127ms, 等）
    - 重点关注 RESEARCH.md 标记的已知退化：
      - `indicator_prescan`: 曾测出 +64% vs v1.0（区间 3.48ms vs 2.12ms）—— 需确认真实值
      - `csv_export_real/real_file`: 数据量约 817MB（v1.0 为 538MB）—— 按数据量归一化后判断

    步骤 4: 记录发现
    在 phase 目录生成 `33-02-BENCH-REPORT.md`，包含：
    - 每个 benchmark group 的当前 median 值和 vs v1.0 baseline 变化百分比
    - 标记所有退化超过 10% 的 group（regression 标记）
    - 对回归 group 分析根因（数据量变化 / 代码路径变化 / 基准噪声）
    - 如果 baseline 过旧导致对比无意义，按 D-19（Claude's Discretion）保存新的 phase33 baseline：
      ```bash
      CRITERION_HOME=benches/baselines cargo bench --bench bench_csv -- --save-baseline phase33
      CRITERION_HOME=benches/baselines cargo bench --bench bench_sqlite -- --save-baseline phase33
      CRITERION_HOME=benches/baselines cargo bench --bench bench_filters -- --save-baseline phase33
      ```

    对 regression 的处理（D-18）：
    - 退化 >10% 且根因在代码路径（非数据量变化）→ 需要修复
    - 退化 >10% 但根因在输入数据量变化（csv_export_real）→ 记录并接受
    - 退化在噪声范围内（<5%）→ 记录但不处理
  </action>
