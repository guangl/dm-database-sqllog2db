   Update `main()`:
```rust
fn main() {
    match run() {
        Ok(Some(stats)) => {
            if stats.has_fatal() {
                std::process::exit(EXIT_FATAL);
            }
            if stats.has_errors() {
                std::process::exit(EXIT_PARTIAL);
            }
            // EXIT_CLEAN (0) is default
        }
        Ok(None) => {}  // non-Run commands: normal exit
        Err(e) => {
            if matches!(e, error::Error::Interrupted) {
                std::process::exit(EXIT_INTERRUPTED);
            }
            eprintln!("Error: {e}");
            std::process::exit(EXIT_FATAL);
        }
    }
}
```

2. For extracting suggestions from errors, since suggestions are stored as `Option<String>` on individual variants and you can't easily extract them from the enum trait object, the simplest approach is:

   Add a `fn suggestion(&self) -> Option<&str>` method to `Error` that delegates to sub-enum methods, and a corresponding method on each sub-error. For example:

```rust
impl Error {
    pub fn suggestion(&self) -> Option<&str> {
        match self {
            Error::Config(e) => e.suggestion(),
            Error::File(e) => e.suggestion(),
            // ... etc
        }
    }
}
```

   But this requires returning `&str` from `Option<String>` fields, which would return a reference to the inner String. Use `.as_deref()`.

   Actually, since `suggestion: Option<String>`, you'd need `fn suggestion(&self) -> Option<&str> { self.suggestion.as_deref() }` on each sub-error. That's clean.

   Alternative: Don't add separate methods — just use the Display impl which already includes the suggestion text (from plan 36-01's Display updates). This is simpler and achieves the goal.

   **Decision**: Keep it simple — the Display impls from plan 36-01 already format the suggestion inline in the error message. The error display in main.rs should just print the error as-is, possibly with a category prefix. The three elements (what/where/how) are embedded in the error message itself.

```rust
Err(e) => {
    if !matches!(e, error::Error::Interrupted) {
        eprintln!("Error: {e}");
    }
    std::process::exit(EXIT_FATAL);
}
```

   This is deliberately kept simple: all the richness (line_number, suggestion, severity) is in the Display impl from plan 36-01. The main.rs error display is just a single line.

   However, for non-fatal errors during processing (in the hot loop), the stderr format already includes `[WARN] file: line: message` from plan 36-02's processor.rs changes.
