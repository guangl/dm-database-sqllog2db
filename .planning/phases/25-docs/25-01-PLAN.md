    **1. 项目概述**
    - 一句话定位：sqllog2db 是解析达梦数据库 SQL 日志并导出为 CSV 或 SQLite 的 CLI 工具
    - 核心特性：流式处理、常量内存、高性能导出
    - 目标用户：DBA、运维人员、审计人员

    **2. 数据流（核心章节）**
    - 使用 ASCII art 绘制数据流图（与 PROJECT.md Key Decisions 中 "ASCII art 替代 Mermaid.js" 一致）
    - 数据流图示例：

      ```
      SQL 日志文件 (.log)
          ↓ SqllogParser — 文件发现与排序（src/parser.rs）
          ↓ dm-database-parser-sqllog — 逐行解析（外部 crate）
          ↓ Pipeline — 可选过滤器/处理器链（src/features/）
          ↓ ExporterManager — 路由到活跃导出器（src/exporter/）
          ↓ CSV（src/exporter/csv.rs）或 SQLite（src/exporter/sqlite.rs）
      ```

    - 补充说明：并行 CSV 路径（rayon map-reduce）和 stats/digest 命令的简化数据流

    **3. 模块划分**
    按 5 大模块 + 支撑模块组织：

    - **配置层（src/config.rs）**：TOML 加载、validate_and_compile 验证、--set 覆写。关键结构：Config。
    - **CLI/编排层（src/cli/）**：clap 子命令分发、handle_run/stats/digest 等工作流。每个子命令一个文件。
    - **Pipeline/特性层（src/features/）**：LogProcessor trait、Pipeline 链、FiltersFeature、SQL 指纹（fingerprint）、参数归一化（normalize）。is_empty 快路径。
    - **导出层（src/exporter/）**：Exporter trait、ExporterKind 枚举（静态分发）、CsvExporter（16MB BufWriter + itoa）、SqliteExporter（batch + PRAGMA）。单活跃导出器优先顺序：CSV > SQLite。
    - **图表层（src/charts/）**：四类 SVG 图表（频次柱状图、延迟直方图、趋势线、用户饼图），plotters SVG-only 后端。
    - **支撑模块**：错误层次（src/error.rs）、解析器（src/parser.rs）、断点续传（src/resume.rs）、日志（src/logging.rs）、i18n（src/lang.rs）。

    每个模块说明：职责、位置、关键抽象（仅 trait/enum 名称，不深入到 struct 字段级别 per D-05）、依赖关系。

    **4. 关键抽象**
    列出最重要的 5-6 个抽象，每个 2-3 句：

    - Exporter trait + ExporterKind 枚举：输出后端接口，ExporterKind 使用静态分派（match）替代动态分发（Box&lt;dyn Trait&gt;）
    - LogProcessor trait + Pipeline：可插拔记录处理链，短路语义（任一 processor 返回 false 即跳过），is_empty 零开销快路径
    - FieldMask：u16 位掩码字段投影，控制 15 个输出字段的启用/禁用
    - TemplateAggregator：流式模板统计引擎，使用 hdrhistogram 以 ~24KB/模板存储耗时分布
    - ResumeState：文件指纹（路径 + 大小 + mtime）持久化到 TOML state 文件，支持增量处理

    **5. 性能设计**
    - 单线程流式处理：常量内存
    - is_empty 快路径：无配置过滤器时零开销
    - 并行 CSV：rayon map-reduce，concatenate 后删除临时文件
    - 编译优化：LTO fat、panic=abort、strip=symbols、opt-level=3
    - 基准性能数据：~5.2M CSV records/sec、~1.1M SQLite records/sec（从 CLAUDE.md 获取）

    **6. 错误处理策略**
    - 非致命解析错误：写入 error log 继续处理
    - 类型化错误层次：Error 枚举 → ConfigError / ParserError / ExportError / FileError 等
    - 退出码映射：0=success, 2=config, 3=IO, 4=export, 130=interrupt

    **写作规范（D-06）：** 全中文撰写。术语第一次出现时附英文（如"管道（Pipeline）"、"导出器（Exporter）"）。ASCII art 数据流图替代 Mermaid.js。模块级深度——不深入到具体 struct 字段定义、trait 方法签名。
