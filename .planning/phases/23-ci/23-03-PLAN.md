    The recording script should run these commands sequentially (per D-06, ~30-45 seconds total):

    ```bash
    # Generate default config
    /Users/guang/Projects/sqllog2db/target/release/sqllog2db init -o config.toml --force
    echo "---"
    # Show partial config (first 10 lines)
    head -10 config.toml

    echo "---"
    # Run export (show progress)
    /Users/guang/Projects/sqllog2db/target/release/sqllog2db run -c config.toml
    echo "---"

    ```

    Execute recording:
    ```bash
    asciinema rec --overwrite /Users/guang/Projects/sqllog2db/site/asciicast/demo.cast \
      --title "sqllog2db: init → validate → run" \
      --idle-time-limit 0.5 \
      --env SHELL,TERM \
      -c "bash /tmp/asciicast-recording.sh"
    ```

    If the direct recording approach fails (asciinema in non-TTY environment), use the programmatic approach:
    ```bash
    # Create a shell script that will be run inside the recording
    cat > /tmp/asciicast-recording.sh << 'RECORDING_SCRIPT'
    #!/bin/bash
    set -e
    # Ensure we use relative paths that work in the recording
    cd /tmp/asciicast-demo
    PROMPT='$ '
    echo "Initializing sqllog2db configuration..."
    ./sqllog2db init -o config.toml --force
    sleep 1
    echo ""
    echo "---"
    echo "Validating configuration..."
    ./sqllog2db validate -c config.toml
    sleep 0.5
    echo ""
    echo "---"
    echo "Running export..."
    ./sqllog2db run -c config.toml
    sleep 1
    echo ""
    echo "---"
    echo "Export complete. Output file: output/sqllog.csv"
    wc -l output/sqllog.csv 2>/dev/null
    RECORDING_SCRIPT
    chmod +x /tmp/asciicast-recording.sh
    ```

    Then retry recording with the script.

| Boundary | Description |
|----------|-------------|

| Threat ID | Category | Component | Disposition | Mitigation Plan |
