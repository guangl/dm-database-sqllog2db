# Configuration Reference

This document describes every configuration option available in sqllog2db. Configuration is written in TOML format. The default configuration is generated by `sqllog2db init -o config.toml --force`. Each section below documents one config block with its fields, defaults, and usage notes.

---

## [sqllog]

Specifies the input log file(s) to process.

```toml
[sqllog]
# Path to DM SQL log file(s). Can be a single file or directory.
path = "sqllogs"
# Optional glob pattern for file matching (e.g., "*.log")
# pattern = "*.log"
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `path` | String | *(required)* | Path to log file or directory containing `.log` files |
| `pattern` | String | `null` | Glob pattern to filter files when `path` is a directory |

**Notes:** Use absolute paths for automation scripts. Relative paths are resolved from the current working directory. Directory scan is recursive and finds all `.log` files by default.

---

## [logging]

Controls application and error logging behavior.

```toml
[logging]
# Log level: trace, debug, info, warn, error
level = "info"
# Optional error log file for parse failures
# file = "error.log"
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `level` | String | `"info"` | Minimum log level (trace/debug/info/warn/error) |
| `file` | String | `null` | Optional file path for parse error output |

**Notes:** Set `level = "warn"` for production use to reduce noise. Parse errors are non-fatal and logged separately; individual records fail without stopping the export.

## [filter.include] and [filter.exclude]

Record-level filtering with AND semantics for include rules and OR-veto for exclude rules.

```toml
[filter]
max_record_limit = 0

[filter.include]
# Each filter rule is a set of field-value pairs (AND within a rule)
# Multiple rules are also AND-ed together
USERNAME = "APP_USER"
# APPGROUP = "WEB"
# IP_ADDRESS = "192.168.1.100"

[filter.exclude]
# Any single exclude match drops the record (OR-veto)
# STMT_TYPE = "SEL"
# USERNAME = "BATCH_USER"
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `USERNAME` | String | `null` | Filter by database username (regex) |
| `APPGROUP` | String | `null` | Filter by application group name |
| `IP_ADDRESS` | String | `null` | Filter by client IP address |
| `STMT_TYPE` | String | `null` | Filter by statement type (INS/UPD/DEL/SEL) |
| `TAG` | String | `null` | Filter by log tag |
| `start_ts` | String | `null` | Filter records after this timestamp |
| `end_ts` | String | `null` | Filter records before this timestamp |
| `max_record_limit` | usize | `0` | Max records to process (0 = unlimited, at `[filter]` level) |

**Notes:** Include and exclude combine as `(include_AND) AND (NOT exclude_OR)`. All fields within one filter rule use AND semantics. Multiple include rules are AND-ed together. Exclude uses OR-veto: any match drops the record. Indicator and SQL content filters use a two-pass pre-scan for transaction boundary detection.

## [template]

SQL template normalization and aggregation engine.

```toml
[template]
# Enable template fingerprinting and aggregation
enable = true
# Normalize SQL by stripping literals and collapsing whitespace
normalize_template = true
# Aggregation mode (currently only "hdrhistogram")
aggregator_mode = "hdrhistogram"
# Latency bucket boundaries in milliseconds
latency_buckets = [1, 5, 10, 50, 100, 500, 1000, 5000]
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enable` | bool | `false` | Enable template analysis |
| `normalize_template` | bool | `false` | Enable SQL fingerprint normalization |
| `aggregator_mode` | String | `"hdrhistogram"` | Statistics aggregation method |
| `latency_buckets` | [usize] | `[1,5,10,50,...]` | Latency histogram bucket boundaries (ms) |

**Notes:** Template analysis requires both `enable = true` and `[charts]` to generate visual output. Dual output automatically writes to both CSV and SQLite when both exporters are configured. `normalize_template` strips comments, folds IN-list values, uppercases keywords, and collapses whitespace.

## [charts]

SVG chart generation configuration. Requires `[template].enable = true`.

```toml
[charts]
# Output directory for SVG chart files
output_dir = "charts/"
# Number of top templates to display
top_n = 10
# Per-chart type toggles
frequency_bar = true
latency_hist = true
trend_line = true
user_pie = true
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `output_dir` | String | `"charts/"` | Directory for SVG chart output |
| `top_n` | usize | `10` | Number of top templates per chart |
| `frequency_bar` | bool | `false` | Generate frequency bar chart |
| `latency_hist` | bool | `false` | Generate latency histogram |
| `trend_line` | bool | `false` | Generate execution trend line chart |
| `user_pie` | bool | `false` | Generate user distribution pie chart |

**Notes:** Charts are generated after template aggregation. Output filenames are fixed: `top_n_frequency.svg`, `latency_histogram_{key}.svg`, `frequency_trend.svg`, `user_schema_pie.svg`. All charts use plotters SVG-only backend — no system fonts or image libraries required.

## [exporter.csv]

CSV export configuration. Higher priority than SQLite when both are configured.

```toml
[exporter.csv]
# Output CSV file path
file = "output/sqllog.csv"
# Overwrite existing file
overwrite = true
# Optional: select specific columns by index (zero-based)
# ordered_indices = [0, 1, 3, 5, 7]
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `file` | String | *(required)* | Output CSV file path |
| `overwrite` | bool | `false` | Overwrite existing file |
| `delimiter` | char | `,` | Column separator character |
| `ordered_indices` | [usize] | `[]` (all fields) | Field projection — zero-based column indices |

**Notes:** CSV uses 16 MB `BufWriter` + `itoa` zero-allocation integer formatting for ~5.2M records/sec throughput. `ordered_indices` selects exact column order and subset. Empty = all fields in default order.

---

## [exporter.sqlite]

SQLite export configuration. Lower priority than CSV when both are configured.

```toml
[exporter.sqlite]
# Output SQLite database path
file = "output/sqllog.db"
# Target table name
table = "sqllog_records"
# Drop and recreate table if exists
overwrite = true
# Optional: select specific columns by index (zero-based)
# ordered_indices = [0, 1, 3, 5, 7]
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `file` | String | *(required)* | Output SQLite database path |
| `table` | String | `"sqllog_records"` | Target table name |
| `overwrite` | bool | `false` | Drop and recreate table if exists |
| `ordered_indices` | [usize] | `[]` (all fields) | Field projection — zero-based column indices |

**Notes:** Uses batch INSERT with PRAGMA optimizations (synchronous=OFF, mmap_size, cache_size) for ~1.1M records/sec throughput. Creates both `sqllog_records` and `_templates` tables when template aggregation is enabled.

---

## [features.replace_parameters]

Legacy SQL parameter replacement. In v1.4+, use `[template].normalize_template` instead.

```toml
[features.replace_parameters]
# Legacy parameter replacement (use [template] instead in v1.4+)
# enable = false
# placeholders = ["?", ":N"]
```

| Field | Type | Default | Description |
|-------|------|---------|-------------|
| `enable` | bool | `false` | Enable parameter replacement (legacy) |
| `placeholders` | [String] | `["?"]` | Placeholder styles to match |

**Notes:** This section exists for backward compatibility with pre-v1.4 configs. In v1.4+, SQL parameter normalization is handled by `[template].normalize_template`. Use the `[template]` section for new configurations.

## Appendix: Config Behavior Notes

### Exporter Priority

Only one exporter is active per run. Priority: CSV > SQLite. When both `[exporter.csv]` and `[exporter.sqlite]` are configured, CSV wins. Remove or comment out the CSV section to use SQLite.

### Pipeline Fast Path

When no filters, template analysis, or charts are enabled, the entire processing pipeline is bypassed via a single `pipeline.is_empty()` check. This zero-overhead fast path means optional features add zero runtime cost when disabled.

### Config Validation

Run `sqllog2db validate -c config.toml` to check configuration before running. Validation reports all errors at once (not fail-fast). Common issues: missing required fields, invalid paths, TOML syntax errors.

### CLI Overrides

Use `--set KEY=VALUE` to override config values from the command line without editing the file:

```bash
sqllog2db run -c config.toml --set exporter.csv.file=custom.csv
```

### Field Order

Fields within each TOML section can appear in any order. The config uses `serde` deserialization, which is order-independent. Optional sections can be omitted entirely — defaults apply for all fields.

### Environment Variables

- `SQLLOG2DB_CONFIG` — Set the default config file path (overridden by `-c` flag)
- `NO_COLOR` — Disable colored terminal output
- `RUST_LOG` — Override log level when using `env_logger`
