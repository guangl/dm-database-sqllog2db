# Milestone v1.12: CLI 体验全面提升

**Status:** ✅ SHIPPED 2026-06-01
**Phases:** 46–49
**Total Plans:** 8

## Overview

全面改善用户与 sqllog2db 的交互体验：错误信息结构化并附带修复建议、配置模板带注释、validate 命令输出清晰、运行时 verbose/quiet 控制、多输入文件 glob 展开。529 个测试，质量门禁全绿。

## Phases

### Phase 46: 错误信息优化

**Goal**: 用户看到的每条错误都包含具体字段名/原因，并附带可操作的修复建议，让用户无需查阅文档就能自助解决
**Depends on**: Phase 45
**Requirements**: ERROR-01, ERROR-02
**Plans**: 1 plan

Plans:

- [x] 46-01-PLAN.md — main.rs eprintln 前缀 Suggestion→hint + 抽取 format_error_output 辅助函数 + Error::Io hint 文本校验 + 单元测试 + tests/integration.rs 端到端 stderr 断言

**Details:**
- 致命错误分支的 `eprintln!("  Suggestion: ...")` 替换为 `format_error_output(&e)` 输出 `  hint: ...` 格式
- 提取 `format_error_output(error: &Error) -> String` 纯函数，使单元测试可直接断言输出内容
- 新增 3 项测试（2 单元 + 1 集成），全套测试零回归

### Phase 47: 配置文件体验

**Goal**: `init` 生成带注释的配置模板让用户一看即懂，`validate` 逐项显示每条校验结果让用户精确定位问题
**Depends on**: Phase 46
**Requirements**: CONFIG-01, CONFIG-02
**Plans**: 2 plans

Plans:

- [x] 47-01-PLAN.md — handle_validate 改 println! 静默通过 + main.rs Validate 分支失败渲染为 [FAIL] + tests/integration.rs 端到端 CLI 输出断言
- [x] 47-02-PLAN.md — CONFIG_TEMPLATE_EN 补全 csv.{file,overwrite,append} 与 sqlite.{database_url,table_name,overwrite,append} 共 7 段行内注释 + tests/integration.rs 注释存在性断言

**Details:**
- validate 通过时只输出 `Configuration valid.`（静默通过，不输出 [OK] 列表）
- validate 失败时输出 `[FAIL] reason\n  hint: ...`，直接 println!/eprintln! 不走日志路由
- CONFIG_TEMPLATE_EN 补全 7 个 exporter 字段注释，实现 CONFIG-01 全字段覆盖

### Phase 48: 日志级别与运行提示

**Goal**: 用户可通过 `--verbose` 和 `--quiet` 精确控制运行时输出的信息量，满足调试与静默脚本两种场景需求
**Depends on**: Phase 47
**Requirements**: LOG-01, LOG-02, LOG-03
**Plans**: 2 plans

Plans:

- [x] 48-01-PLAN.md — opts.rs `-v` 改 bool + main.rs 移除 debug 映射并扩展 handle_run 调用 + cli/run/mod.rs 增 verbose 参数与 ProgressBar 条件化 + 35+ handle_run 调用点迁移 + 端到端 CLI 测试覆盖 LOG-01/LOG-02
- [x] 48-02-PLAN.md — sqlite_parallel 返回值对齐 csv_parallel 形态 + handle_run 顺序路径收集 per_file_counts + verbose 摘要前输出每文件 `Processed:` 明细 + 端到端测试覆盖 LOG-03

**Details:**
- verbose 从 u8 Count 改为 bool 布尔标志，语义从日志级别控制转为运行时展示控制
- show_progress 条件改为 `!quiet && !verbose`
- run() 返回 Option<(ErrorStats, bool)> 携带 quiet 信号到 main() 控制摘要输出
- verbose 摘要差异化：顺序路径输出每文件 `Processed: <path> — N records` 明细

## Milestone Summary

**Key Decisions:**

- `hint:` 前缀（lowercase, two leading spaces）作为所有致命错误的规范格式
- validate 静默通过策略（D-03）：通过时仅输出 `Configuration valid.`，不输出 [OK] 列表
- verbose 语义从「调整日志级别」转为「展示运行时进度详情」
- glob 展开通过现有 `glob` crate 实现，不引入重量级依赖
- assert_cmd / predicates 作为 dev-dependency 引入，增强 e2e CLI 测试能力
