    ```bash
    #!/usr/bin/env bash
    # 收集 criterion 输出的 estimates.json，合并为单一 JSON artifact。
    # 输出文件：bench-results-${SHA短}.json，包含 timestamp、commit_sha、benchmarks（每组 mean_ns + stddev_ns）。
    # 依赖：ubuntu-latest 内置 jq、find、awk（无需额外安装）。

    set -euo pipefail

    SHA="${GITHUB_SHA:-$(git rev-parse HEAD)}"
    SHORT_SHA="${SHA:0:8}"
    TIMESTAMP="$(date -u +"%Y-%m-%dT%H:%M:%SZ")"
    OUTPUT="bench-results-${SHORT_SHA}.json"

    if [ ! -d "target/criterion" ]; then
        echo "ERROR: target/criterion not found; run cargo bench first" >&2
        exit 1
    fi

    # 每个 estimates.json 路径形如：target/criterion/<group>/<bench_id>/new/estimates.json
    # 用 awk 提取末尾 4 段中的 <group>=NF-3, <bench_id>=NF-2，避开硬编码路径深度（Pitfall 5）。
    benchmarks_json="$(
        find target/criterion -name 'estimates.json' -path '*/new/estimates.json' \
        | while IFS= read -r f; do
            group="$(echo "$f" | awk -F/ '{print $(NF-3)}')"
            bench_id="$(echo "$f" | awk -F/ '{print $(NF-2)}')"
            jq --arg g "$group" --arg i "$bench_id" \
                '{key: ($g + "/" + $i), mean_ns: .mean.point_estimate, stddev_ns: .std_dev.point_estimate}' \
                "$f"
          done \
        | jq -s 'map({(.key): {mean_ns: .mean_ns, stddev_ns: .stddev_ns}}) | add // {}'
    )"

    jq -n \
        --arg ts "$TIMESTAMP" \
        --arg sha "$SHA" \
        --argjson benchmarks "$benchmarks_json" \
        '{timestamp: $ts, commit_sha: $sha, benchmarks: $benchmarks}' \
        > "$OUTPUT"

    echo "Benchmark results written to $OUTPUT"
    cat "$OUTPUT"
    ```

    ```yaml
    name: Benchmark

    on:
      pull_request:
        branches: [main]
      push:
        branches: [main]

    env:
      CARGO_TERM_COLOR: always

    jobs:
      benchmark:
        name: Run Benchmarks
        runs-on: ubuntu-latest
        timeout-minutes: 30
        # Bench 失败不阻塞 PR merge（仅作 informational，per CONTEXT 注意事项）
        continue-on-error: true
        steps:
          - uses: actions/checkout@v6

          - name: Install Rust
            uses: dtolnay/rust-toolchain@stable

          - name: Cache cargo
            uses: Swatinem/rust-cache@v2

          - name: Run benchmarks
            run: cargo bench

          - name: Collect benchmark results
            run: bash scripts/collect_bench_results.sh
            env:
              GITHUB_SHA: ${{ github.sha }}

          - name: Upload benchmark artifact
            uses: actions/upload-artifact@v4
            with:
              name: bench-results-${{ github.sha }}
              path: bench-results-*.json
              retention-days: 60
    ```

    **关于触发条件**（Open Question #2 in RESEARCH.md）：选择同时监听 pull_request 和 push to main（与 ci.yaml 触发条件一致）——PR 时用于对比，push to main 时记录每次合并后的永久基线。Claude's Discretion 范围内做出此决策。

    **关于 retention-days**：选 60 天，落在 RESEARCH.md 推荐范围 30-90 内，平衡存档需求与 GitHub artifact 配额。

    **关于 continue-on-error**：CONTEXT.md "注意事项" 明确要求"CI benchmark 不应阻塞 PR merge（失败只产生警告，不 fail CI）"。在 job 级别设置 `continue-on-error: true`，bench 失败时 workflow 仍标为 success，PR merge 不阻塞。

| Boundary | Description |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-45-CI-02 | Denial of Service | bench job 超时占用 runner | mitigate | timeout-minutes: 30 + continue-on-error: true 限制单 job 资源使用；ubuntu-latest 单 runner 不阻塞 ci.yaml 的 matrix job |
| T-45-CI-03 | Tampering | 第三方 action 引入恶意代码 | mitigate | 所有 action 复用 ci.yaml 已验证版本（actions/checkout@v6, dtolnay/rust-toolchain@stable, Swatinem/rust-cache@v2），新增的 actions/upload-artifact@v4 为 GitHub 官方维护 |
